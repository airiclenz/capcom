---
title: A CLI write warns while another session holds the Tree lock; the holder's own writes and writes of the Issue the lock is held for stay silent
---

Status: Accepted; amended 2026-11-22.

A mutating CLI command still writes while the Tree lock of this worktree is held, but it now says
so: it adds one warning naming the holder and the purpose, unless the write targets the Issue whose
id is the lock's purpose. It never refuses a write and never changes an exit code. Since
2026-11-22 the lock record names the holder process, and a write made under it stays silent
whatever it targets and renews the heartbeat; the warning another session sees tells it to ask the
user before writing more. Read `adr-0017-decision` for when it warns, where the warning goes and
why, then `adr-0017-amend-1122` for the holder process and the new warning words, then
`adr-0017-rejected` for a `--token` flag on every write, blocking writes, a stderr-only warning and
leaving the CLI silent.
