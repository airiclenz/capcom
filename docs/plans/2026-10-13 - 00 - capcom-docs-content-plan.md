**Goal:** Give capcom a complete, versioned user manual under `docs/site/` that the airiclenz.com
Starlight site renders at `/capcom/`. The CLI reference is generated from the cobra command tree and
kept current by a test; every command gains `Long` and `Example` help text.

**Sources:** `README.md`; `docs/format.md`; `docs/migrating-from-beads.md`; `.capcom/knowledge/glossary/`; `.capcom/knowledge/docs-layout.md`; `internal/cli/root.go`; companion plan `2026-10-13 - 01 - capcom-manual-site-plan.md` (airiclenz.com)

**Ratified design calls** (user, 2026-10-13):
- **Help text:** every command and subcommand gets `Long` and `Example`; examples are drawn from the README Usage block.
- **CLI reference:** generated by `go run ./cmd/gendocs`, committed under `docs/site/reference/cli/`; a Go test fails when it is stale.
- **Site consumption:** airiclenz.com copies `docs/site/` from a pinned capcom ref; capcom needs no Node or site tooling.
- **Moved docs:** `docs/format.md` and `docs/migrating-from-beads.md` move into `docs/site/`; the old paths keep a one-line pointer stub.
- **Generator shape:** internal/cli exports Command(); internal/clidoc.WriteReference renders it; the capcom binary never links cobra/doc (plan author, 2026-10-13, after regression check).

**Docs page contract** (binding for every file under `docs/site/`):
- YAML frontmatter with `title`, `description` (one sentence) and `sidebar: { order: <n> }`; no body H1.
- Links between pages are relative `.md` links (they work on GitHub; the site rewrites them). Links outside `docs/site/` are relative repo paths.
- Use glossary terms (Issue, Note, Tree lock, Parent — never "epic"). Never pin a capcom version number in prose.

**Standing requirements:**
- skills: coding-standards
- Host is memory-limited: test single packages with `GOMEMLIMIT=2GiB go test -count=1 ./<pkg>/...`; never `-race` on `./...`; never two test commands at once.
- User-visible changes get an `## [Unreleased]` CHANGELOG line (via the item sidecar).
- No AI attribution in commits, code or docs.

**Out of scope:** the Astro/Starlight site itself (companion plan); release tooling changes; VERSION, tags, CHANGELOG release headings; the open issue `block-work-loop`.
