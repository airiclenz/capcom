---
title: The Tree lock is a token with a heartbeat, not a held process
---

Status: Accepted; amended 2026-10-26.

A Tree lock belongs to one worktree and is held by an agent session through a token and a heartbeat,
not by a process; it goes stale after the TTL and is taken over only on request. Read
`adr-0005-decision` for the mechanism and its reasons, then `adr-0005-amend-1026` for a heartbeat
dated more than one TTL ahead, which is also stale, then `adr-0005-rejected` for a per-clone lock,
pid liveness and an enforcing hook.
