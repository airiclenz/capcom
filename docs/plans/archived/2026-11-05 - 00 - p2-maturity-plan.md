**Goal:** Close the five P2 issues under `code-maturity`: move off the archived YAML module; pin every `--json` kind, every `--kv` record and every exit code with golden tests; prove capcom reads every store format it wrote; stress real concurrent processes; and measure whole commands at scale with a CI regression check.
**Date:** 2026-11-05
**Status:** unexecuted
**sized for:** ~200k-context host
**base:** c9b89ff

**Sources:**
- `.capcom/issues/code-maturity/yaml-module-swap.md`, `json-golden-tests.md`, `format-fixture-tests.md`, `concurrent-process-stress.md`, `command-benchmarks.md` (each item's Acceptance)

- Notes `cli-test-harness`, `coding-conventions`, `store-layout`; ADR-0008 (release gate)

**Ratified design calls:**
- **Golden scope:** every `kind` the code emits gets a golden file, not only the kinds `json-output.md` names; item 5 completes the doc's kind list. (Airic, 2026-11-05)
- **Format fixtures:** written by hand from the format rules in `internal/config/config.go`, never generated by old release binaries. (Airic, 2026-11-05)
- **CI placement:** stress runs in `.github/workflows/stress.yml`, benchmarks in `.github/workflows/bench.yml`; neither is a job in `ci.yml`, so neither gates a release. (Airic, 2026-11-05)
- **Volatile values:** no clock is injected; the golden helper replaces, by one documented regexp each, timestamps and date-only Log stamps (<TIME>/<DATE>), etags (<ETAG>), temp paths in native and JSON-escaped form (<DIR>), the version (<VERSION>), lock tokens (<TOKEN>), host (<HOST>) and user (<USER>), in both the JSON and the KEY=VALUE forms. (plan writer, 2026-11-05, after the regression check)
- **Bugs found:** a bug a stress, fixture or golden test finds is fixed in the item that found it, with a regression test and a `fix(…)` CHANGELOG entry in the sidecar.
- **Format raise:** fixtures assert today's raise-with-warning behaviour; issue `explicit-format-upgrade` (open, out of scope) updates that assertion when it lands.

**Standing requirements:**
- skills: coding-standards
- Tests on the Pi: single packages with `GOMEMLIMIT=2GiB`, never `-race` on `./...`, never two test commands at once; stress with `CAPCOM_STRESS_WORKERS=4`.
- CLI tests follow Note `cli-test-harness`: `runCLI`, real temp git repo, never `t.Parallel()`.
- New tools only at pinned versions (`go run <module>@<version>`), never `@latest`; no new module in `go.mod` except item 1's swap.
- Every authorised deviation from item text lands as a dated NOTES line under the item.

**Out of scope:**
- `explicit-format-upgrade`, `compat-policy-doc`, `split-cli-package`, `scheduled-agent-eval`, `html-export`
- Fixing slow commands the benchmarks expose (item 13 files them as issues)
- A clock-injection seam in production code

NOTES (2026-11-05): compareGolden takes the store root as a third argument, compareGolden(want, got, root string) error, since the <DIR> regexp is built from the temp root; it stays pure (no t, no file access) and the harness test calls it directly.

NOTES (2026-11-05): goldenJSONDir is made absolute when the test binary starts, because runCLI t.Chdir-s into the store and a relative testdata path would be written there.

**What:**
**Goal:** `internal/cli` has a golden JSON harness with an `-update` flag and a fixed seeded store, and golden files under `internal/cli/testdata/json/` pin the kinds `issue`, `issue-list`, `ready`, `next` (both a found Issue and `data: null` with exit 4), `context`, `deps`, `dep-graph`, `search` (`match: all` and `match: any`), `prime`, `recap`, `check`, `version`, `reindex`, `init`, `agents`.
**Approach (assumed at the header base):** new `internal/cli/golden_test.go` holds the harness: `var isGoldenUpdate = flag.Bool("update", …)` as `internal/ui/harness_test.go` does it; a `newGoldenStore(t)` seeding a fixed store through `runCLI` (parents, deps, a standing issue, Log entries, related, Notes) so ids and bodies are fixed; `assertGoldenJSON(t, kind string, stdout string)` that normalises `<TIME>`, `<ETAG>`, `<DIR>` by documented regexps and compares with `testdata/json/<kind>.golden.json` (a variant suffix such as `next-empty` where one kind needs two files). New `internal/cli/golden_read_test.go` holds one test per kind above. Comparison is byte-exact after normalisation, so `[]` versus `null` and field order are pinned.
**Regression guard.** The normaliser replaces the version value with `<VERSION>`, so a release's `VERSION` bump leaves the goldens green. `<DIR>` matches the JSON-escaped temp root (as well as the native one) and `filepath.ToSlash`-es the rest of that value, stated in the harness doc comment. `<TIME>` (or a separate `<DATE>`) also matches the date-only Log stamp (`- YYYY-MM-DD Test Author: …`). `newGoldenStore` commits the seeded store (`runGit`/`commitAt` as `lock_test.go` and `recap_test.go` do), and `recap` runs bare, never `--since <ref>`. The harness has a pure `compareGolden(want, got string) error` (normalise, byte-compare) that the harness test calls; `assertGoldenJSON` wraps it.
