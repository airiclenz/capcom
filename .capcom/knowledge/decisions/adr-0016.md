---
title: An agent session keeps its Lock token in a token file keyed by worktree and purpose under the git common dir
---

Status: Proposed.

An agent session keeps its Lock token (ADR 0005) in a token file that capcom writes for it under
the git common dir, keyed by the worktree and the lock's purpose. `capcom lock acquire` and
`capcom start` write it; an acquire or start that names the same purpose without `--token` resumes
from it; `capcom lock release` and `capcom finish` delete it. The session no longer has to carry
the token across turns, shells or a context compaction: naming the purpose again, which for
`capcom start` is the Issue id `capcom prime` lists as doing, is enough. Read `adr-0016-decision`
for the file, how it is used, its cost and how it meets each constraint of `lock-token-recall`,
then `adr-0016-rejected` for a `--token-file` flag, a token taken from a harness session id, and a
printed resume line alone.
