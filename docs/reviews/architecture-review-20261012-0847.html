Problem
Issue and Note write verbs are parallel copies in cli: the load → triage → claim-check → etag → validate → write sequence is spelled out 7 times, and the order is documented in errors.go:236 rather than enforced.
Solution
A deep module, one value per Tree kind (Issues, Notes), owns the alias functions, the claim check, triage, the etag guard, validation and the path convention, and returns Written{ID, Path, ETag} instead of a rendered Result.
Wins

  • leverage: one interface, 9 verbs
  • delete 4 aliasFn helpers
  • tests hit Kind without runCLI
  • close stops unpicking Result.Data
  • Note parity: mv --if-match, full errors

Evidence: relativeSlashPath ×21 across 10 files; etag check inlined ×5; validation→*Error ×5; close.go:156 casts Data.(map[string]string) to recover the etag.

Problem
issue/file.go and knowledge/note.go carry the same ~75-line frontmatter parser, separate Error types and different serialisation, so "canonical form" means two things.
Solution
Extract a frontmatter module (split, decode with a per-kind field callback, encode, one Error{Path, Line, Message}); Issues and Notes keep only their field tables. rawfm stays — it is deep and must read unparseable files.
Wins

  • check drops its type switch
  • parser tests written once

ADR 0009 — keep strictness: unknown keys stay errors in the shared decoder. Unifying the quoting policy may reformat existing files; capcom fmt covers that, but it is a visible diff.

Problem
The index is deep inside but leaks three things across its seam: callers must call Refresh before any query, cli classifies warnings by matching message text, and index/walk.go re-implements the ADR 0001 walk with different orphan wording than tree.
Solution
index.Open returns a fresh index (or refreshes lazily on first query); Warning carries a typed kind; the directory walk and the duplicate id/alias rules come from tree.
Wins

Problem
Tests fake git and gh by matching argv strings, so changing any command line breaks fakes in unrelated tests.
Solution
Put the seam at repository operations; the exec adapter owns the argv, the test adapter owns semantic state.

  • fakes describe state, not argv
  • locality: argv in one adapter

ADR 0007 (real git in tests) covers the shipped binary; cmd/release already fakes at argv level for gh, so this moves an existing fake rather than adding one. Real-git coverage of the git adapter can stay.

Problem
Small shallow modules and domain facts sit on the wrong side of their seam: the deletion test removes the issue label/body wrappers at no cost, and cli owns git argv, claim detection and the config path.

  • git argv leaves cli
  • store owns its format raise

Defects found on the way

Not part of this review's scope — run /code-audit to confirm and triage.

  • mv leaks an absolute path. cli/mv.go:192 passes a moved issue's parse failure through issueFailure, which copies issue.Error.Path unchanged; that path is absolute (issue/move.go:84). noteMoveFailure relativizes. Drift between the copies of candidate 1.
  • lock touch on a free lock reports an empty worktree. lock.Touch returns a zero Status on ErrNotHeld; emitLock (cli/lock.go:294) renders lock.Status{Key: status.Key}, so the key is empty.
  • know add reports only the first validation problem, with no line (cli/know.go:337); writeNoteFile reports all, with lines.
  • Move rollback is not byte-exact for CRLF files — undo writes through WriteFileAtomic, which normalises to LF (tree/move.go:186, acknowledged in a comment).
  • prime discards the Refresh report (prime.go), so index "left out" warnings never reach the Briefing — possibly intended, since the check count covers them.

Top recommendation

1 · One node-store module per Tree kind

It is the widest shallow surface in the codebase — 9 verbs, 7 copies of one sequence — and the copies have already drifted into a user-visible defect (the mv absolute path). Candidates 2 and 4 then land inside it as its internals.
