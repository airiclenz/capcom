---
title: capcom ui remembers its layout in a machine-written state.yaml beside the hand-owned config.yaml
---

Status: Accepted. Amended 2026-10-16: the width is stored as `ui.sidebar_ratio`, a ratio of the
terminal's width, so the split holds when the terminal is resized. Amended 2026-10-17: the stacked
layout's divider, below 90 columns, is stored apart as `ui.stacked_ratio`, a ratio of the body's
height.

`capcom ui` remembers the sidebar width, and the sidebar's height in the stacked layout, between
runs in a second per-user file,
`<os.UserConfigDir>/capcom/state.yaml`, which only it writes; the user config `config.yaml`
(ADR 0011) stays hand-owned and is never rewritten. Read `adr-0014-decision` for the file, when it
is written and how it is read, then `adr-0014-rejected` for rewriting `config.yaml` in place,
storing columns, and writing on quit. The tab and the selection on each tab are remembered per
worktree, in `ui-state.yaml` under the git dir (ADR 0015).
